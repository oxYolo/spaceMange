## 0. 设计准则：让 UI 成为接口模型的投影

前两版的共同问题是**以外部系统为参照系**：v1 照搬 Axure 的业务分类，v2 照搬开源系统的功能平面。两者都会引入后端并不存在的概念（最典型的就是「文本数据模块」——后端没有任何文本数据的表或端点）。

v3 换一个方向：**先读接口模型，再画页面**。三条准则贯穿全篇：

| 准则 | 含义 | 检验方式 |
|:---|:---|:---|
| **UI 域 = 后端聚合根** | 一个一级导航域，对应一个（或一组强耦合的）后端聚合根 | 19 个业务 Controller 必须各有归属，且无域对应不到 Controller |
| **UI 页 = 生命周期阶段** | 二级页面是聚合根在「接入 → 入库 → 编目 → 配样式 → 挂图 → 发布 → 加工」链条上的阶段 | 每个页能说出对应哪几个端点 |
| **UI 交互 = 端点** | 每个按钮 / 表列 / 表单字段能落到具体端点与参数 | 开启「接口注释」逐点核对 |

按此准则，从接口模型里读出 8 个关键事实（下面每一条都直接决定了一个设计决策）：

| # | 接口模型事实 | 证据 | 由此产生的设计 |
|:--:|:---|:---|:---|
| 1 | **单表两型**：矢量与栅格是同一张 `sdms_layer_content` 的两个 `layerType` / `uploadFileType` 取值，不是两个模型 | `LayerContentController` 36 端点无一按类型拆分；`LayerContentEntity` 用 `rasterCount`/`rasterDatatype` 等字段容纳栅格差异 | 矢量/栅格**不拆两个平级页**，改为页内「类型维度」筛选（层代号 ①②③） |
| 2 | **无文本数据模型**：没有文本数据的表、实体或端点 | 全库检索无对应 Controller / Mapper | **删除「文本数据」模块**（v1/v2 的凭空发明） |
| 3 | **三维是独立聚合根**：独立表 `sdms_model3d`、独立状态机 0~5、独立 MQ 队列 `Model3dConvertQueue`、独立上传协议 `init/part/complete` | `Model3dController` 8 端点 | 三维**独立成域**，不挂在「数据资源」之下 |
| 4 | **加工是统一异步模型**：10 类工具共用 `sdms_tool_his` + `origin` 1~10 + `taskId` 轮询 + `storageLayer` 入库 | `/layerTool/*` 9 个端点 + `/topology/check` 返回值与 `storageLayer` 同构 | 工具**收敛为一个工具箱 + 一个任务中心**，不按「矢量工具/栅格工具」拆页 |
| 5 | **样式与符号正交于图层**：独立表 `sdms_datastyle` / `sdms_symbol`，样式带引用计数，可复用 | `DataStyleController` 35 端点含 IsExists / GetAllFolders / SLD 解析 | 独立「样式与符号」域，而不是图层编辑器的附属页签 |
| 6 | **发布是三段链**：`Map`（容器）→ `MapRelation`（挂载图层，带 `dataStyleID` 与 `min/maxScaleDenominator`）→ `ServerInterface`（产出服务） | 三个 Controller 共 36 端点 | 「地图与发布」域内三视图（工作台 / 服务与缓存），关联表语义直接在 TOC 与比例尺区间上体现 |
| 7 | **编目是三正交轴**：分类是树（`DataType`，`ParentID`）、标签是扁平表（`DataTag`）、标签↔资源↔地图是多对多中间表（`TagRelation`） | 三个 Controller 22 端点 | 「编目管理」域内三页，**标签关系独立成页**（v2 缺失） |
| 8 | **字典是软绑定**：`DataType.DictCodeID` 存 code 字符串而非外键；字典分主从两级 | `DicDataTypeController` + `DicDataCodeController` 11 端点 | 字典归入「系统」域（不是编目），并在 UI 上标注软绑定语义 |

外加两个专项控制器（`UploadController` / `KneeCoordinatesController`，共 4 端点）体量不足以独立成域，按语义并入「数据资源 → 数据接入」。

## 2. 信息架构

```
顶栏   系统名 · 环境标识 | 全局资源检索 | 接口注释开关 | 本页接口 | 用户

左侧（按聚合根组织，可折叠）
① 数据资源            → 资源总览 · 数据接入
② 三维资源            → 三维数据
③ 编目管理            → 数据分类 · 数据标签 · 标签关系
④ 样式与符号          → 样式库 · 符号库
⑤ 服务与预览          → 服务与缓存
⑥ 处理与分析          → 工具箱 · 拓扑检查 · 任务中心
⑦ 系统                → 字典管理 · 操作日志

路由表
#/data                #/ingest
#/model3d
#/catalog/{type|tag|tagrel}
#/style               #/symbol
#/publish
#/tools               #/tools/topology        #/tasks
#/system/{dict|log}
```

**「类型维度」与「分类维度」是两条正交轴。** 放在同一页里，但语义严格区分：

- **类型维度**（`state.dataType`）= 全部 / 矢量 / 栅格 —— 对应 `LayerContent.layerType`，是**平铺的枚举**；
- **分类维度**（资源目录树）= 因子库 / 空间数据 / 承灾体 / 基础底图 —— 对应 `GET /layerContent/getLayerTree`（**返回压缩串，须先解压**），是**树**。

两者叠加发布态（`publishStatus`）与所有者，构成四维可组合筛选。

### 资源详情页签 = 资源生命周期

v2 的 7 页签（概览/数据/样式/服务/**缓存**/元数据/活动）里有「缓存」——但接口模型里没有 `CacheController`，缓存只是 `MapRelation` 的切片任务（`IsExistTilesTask`）。v3 把它**并入「服务与发布」页签**，页签收敛为 6 个，顺序即生命周期：

```
概览 → 数据与要素 → 样式 → 服务与发布 → 元数据 → 活动
```

其中「数据与要素」按 `layerType` **自适应**：栅格展示栅格结构（行列/波段/像元/NoData）+ 像元统计 + 栅格工具入口；矢量展示字段定义（`GetFieldByLayerId`）+ 属性表预览 + 空间查询/要素编辑/导出。

## 5. 接口注释机制

顶栏「接口注释」开关打开后：

- 全页每个交互点出现**虚线框**（GET 绿 / POST 蓝 / DELETE 红 / PUT 橙）；
- 右上角出现**编号角标**，编号 = 本页去重后的接口顺序；
- 悬浮角标显示「方法 · 路径 · 说明 · 入参 · 返回 · 注意事项」；
- 右上「本页接口」列出**编号 ↔ 端点**对照清单，点角标可跳转定位。

角标为 `position:absolute`，**不参与布局**。页面面包屑统一显示「**接口依据：xxxController（N 端点）**」，替代 v2 的「版式参考：GeoNode / GeoServer」——不再把外部系统当设计依据。

|:---|:---|
| **裸返回（无 `Result` 外壳）** | `GetAllCount`(Integer)、`GetAllListByName`(ListResultOutput)、`GetPageListByName`(PagedResultOutput)、`GetAllListByMapID`、`GetLayerAttrTabledDetail`(String)、`InsertImageLayer`(MapEntity)、`Delete`/`DeleteLayer`(boolean)、`GetLayerAttrTableByWhere`/`GetAttrtableByLayerId`(PagedResultOutput)、`InsertAttrtable`/`DeleteAttrtable`(boolean)、`GetFieldByLayerId`(List)、`ValidateCondition`(boolean)、`layerField/GetAllList`、`dataType/GetAllListByDataType`、`dataType/GetDetailByName`、`dataTag/GetAllListByDataType`、`dataStyle/InsertGeoServerStyle`(void) |
| **压缩返回** | `getLayerTree` / `getLayerTreeByType` 返回 `CompressionUtils.compressString` 后的字符串，前端须**先解压再 `JSON.parse`** |
| **字段名单数** | `ListResultOutput` 的字段是 `item` 而不是 `items` |
| **参数名大小写混用** | `mapID` / `mapId` / `mapid`、`layerID` / `layerId`、`PageSize` / `pageSize`、`PageIndex` / `pageIndex`、`MapId`。逐个端点按文档书写，**不能统一转换** |
| **表单 vs JSON** | `map/Insert`、`map/Update`、`map/GetAllListByName`、`layerContent/InsertImageLayer` 无 `@RequestBody`，走 `application/x-www-form-urlencoded` |
| **GET 带 Body** | `dataStyle/GetXmlContent` 为 GET + `@RequestBody`，部分网关/客户端会丢弃请求体 |
| **无类级前缀** | `KneecoordinatesController` 两端点路径自带 `/Kneecoordinates/...` |
| **异步任务四段式** | 9 个图层工具 + `topology/check` + `model3d/{id}/convert` 统一为「提交 → 返回 taskId → `layerTool/getList?origin=N` 轮询 → `storageLayer` 成果入库」。入库后：`sdms_tool_his.storage=1`、成果图层 `isShow=1`、`layerType=targetId` |
| **拓扑容差不一致** | `/topology/check` 默认 `0.00001`，`/topology/checkSync` 缺省 `0.001` |
| **矩阵是字符串** | `ReclassificationDTO.matrix` 是 JSON **字符串**，不是数组；`type=1` 用 `{max,min,value}`，`type=2` 用 `{old,value}` |
| **像元值上限** | `getTifValues` 在像元值 > 50 时返回 `fail(400,"图层像元值过多，请选择其他方法！！！")`，需回退到区间分类 |
| **三维分片约束** | 非最后分片必须 ≥ 5 MiB；`modelType` 与 `srcFormat` 必须匹配；TILESET 免转换；转换并发度 `max-concurrent: 1` |
| **字典软绑定** | `sdms_datatype.DictCodeID` 存 code 字符串而非外键，删除字典代码不会级联影响分类 |
| **空壳端点** | `systemUser/GetUserDataByUserCodeAsync` 返回 `null`，不建 UI |

## 7. 与历史版本的差异

| 维度 | v2 | v3（本版） |
|:---|:---|:---|
| 设计依据 | 主流开源系统的功能平面 | **后端接口模型**（8 条事实 → 8 条决策） |
| 一级域 | 6（数据目录 / 地图与发布 / 样式与符号 / 处理与分析 / 目录与字典 / 系统） | **7**（数据资源 / 三维资源 / 编目管理 / 样式与符号 / 地图与发布 / 处理与分析 / 系统） |
| 文本数据 | 有（凭空发明） | **删除** |
| 矢量 / 栅格 | 两个平级页 `#/catalog/vector` `#/catalog/raster` | **合并为「资源总览」页内的类型维度筛选** |
| 三维 | 挂在数据目录下 `#/catalog/3d` | **独立成域** `#/model3d` |
| 标签关系 | 无 | **独立成页** `#/catalog/tagrel` |
| 字典 | 与分类/标签同级 | 归入**系统**域 |
| 数据接入 | 散落在新建弹窗 | **独立成页**（两条上传通道并列） |
| 矢量工具 / 栅格工具 | 两个平级页 | **收敛为一个工具箱**，页内三类切换 |
| 资源详情页签 | 7 个（含「缓存」） | **6 个**（缓存并入「服务与发布」），顺序即生命周期 |
| 页面数量 | 17 | 15（更少，但覆盖的 Controller 更多） |

## 8. 未纳入本版（建议后续）

| 事项 | 说明 |
|:---|:---|
| 真实地图引擎接入 | 原型用程序化 SVG 底图占位；落地时接 OpenLayers / Cesium，WMS/WMTS 直接吃 `serverInterface` 返回的地址 |
| 权限模型 | 后端权限由 whulri 基座提供，本原型未做按钮级权限控制 |
| 模型管理 / 权重计算 | 原 Axure 稿有此模块，但计算服务不在 `geodata-service`（200 端点内无对应接口），按准则「无端点则不建页」故不纳入 |
| 真实压缩串解压 | `getLayerTree` 的压缩/解压算法在 SDK 侧，原型仅标注 |
