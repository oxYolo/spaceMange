# 模块功能设计与按钮合理性评审

> 评审对象：`docs/prototype/sdms-console.html`（v3.1，赤壁市示例数据）
> 评审方法：抽取全部 182 处 `data-api` 标注 + 23 处工具箱 `api:'…'` 间接引用，逐一对照 `const API` 注册表（198 端点）与 `docs/接口文档.md`
> 评审时间：2026-10-10

## 0. 结论摘要

| 指标 | 数值 |
|:---|:---|
| UI 交互点（去重按键计） | 108 个端点被 UI 直接标注 |
| 间接引用（工具箱/上传器） | 23 个端点 |
| 孤儿引用（标注了不存在的端点） | **1 处，已修复**（`marByMapId` → `marByLayer`） |
| P1 问题 | **3 项**（删除语义不一致 / 地图本体无编辑删除入口 / 日志导出无端点） |
| P2 问题 | 8 项（CRUD 补全类，均不阻塞评审） |
| 注册表未标注端点 | 91 个，处置分类见 §9 |

**总评：信息架构与按钮粒度合理，域-页-端点三层映射自洽；主要风险集中在「删除语义」与「地图本体的管理入口」两处，均为 P1，建议在进入开发前定案。**

## 1. 数据资源（`#/data`）—— 系统的默认落地页

**设计意图**：后端矢/栅共用一张 `sdms_layer_content`（`layerType` 区分），所以不设两个平级模块，而是「统一资源模型 + 页内类型维度筛选」。左侧目录树（`getLayerTree`，返回压缩串）是**分类维度**，与筛选条的类型/发布态/所有者三维**正交**，四维可组合。右侧详情抽屉 6 页签对应资源的六个生命周期切面。

### 工具条按钮

| 按钮 | 端点 | 作用 | 评价 |
|:---|:---|:---|:---|
| 新建资源 | `POST /layerContent/Insert` | 表单式建资源（form 提交，无 `@RequestBody`） | ✓ |
| 上传文件 | `POST /upload/.../AddFiles` | 打开分片上传弹窗 | ✓ |
| 批量归档 | `POST /layerContent/updateList` | 批量改 `parentId` 移动目录 | ✓ 端点支持；措辞建议改「移动到目录」更准确 |
| 批量导出 | `POST /layerContent/downloadAttrInfoBySwitch` | 导出查询结果（MinIO 地址） | ⚠️ P2：端点是单图层导出，「批量」需前端循环调用，后端无批量导出端点 |
| 任务中心 | `GET /layerTool/getList` | 跳转 | ✓ |
| 批量打标 | `POST /tagReleation/MultiInsert` | 多资源×多标签 | ✓ 端点天生批量 |
| 批量发布 | `publishService` | 发布为 OGC 服务 | ⚠️ P2：端点单图层，批量=循环；建议 UI 上限制勾选数并提示耗时 |
| 批量删除 | `POST /layerContent/Delete` | 删资源 | ❌ **P1**，见 §8-1 |

### 目录树

| 按钮 | 端点 | 评价 |
|:---|:---|:---|
| ↻ 刷新 | `GET /layerContent/getLayerTree` | ✓ 返回压缩串须先解压（已标注） |
| ＋ 新增分类 | `POST /dataType/Insert` | ✓ 就地建分类，不打断浏览 |

### 详情抽屉 6 页签（30+ 按钮）

| 页签 | 按钮 → 端点 | 评价 |
|:---|:---|:---|
| 概览 | `layerDetail` 读取 | ✓ 主入口，支持全屏 |
| 数据 | 要素编辑 `editVectorFeatures`（GeoJSON） | ✓ 文档 2.8 有端点 |
| 数据 | 导出 `OutputShpFileData` / 下载 TIF | ✓ 注意 `layerID` 与其它端点 `layerId` 大小写不同名（已标注） |
| 数据 | 删除 `DeleteLayer` | ✓ 连带清理发布信息，单个删除用这个是对的 |
| 数据 | 新增字段 `fieldInsert` | ⚠️ P2：后端还有 `fieldUpdate`/`fieldDelete`，字段行内缺编辑/删除按钮 |
| 数据 | 属性表：分页读取 / 空间查询（5 种选集模式）/ 条件筛选 / 编辑记录 / 导出 | ✓ 覆盖 `attrTable`/`attrSwitch`/`attrWhere`/`attrUpdate`/`attrDownload`；缺 `attrInsert`/`attrDelete`（P2） |
| 样式 | 色带库 / 查看 SLD / 另存为样式 | ✓ |
| 服务与发布 | 发布 / 服务地址 / 复制 / 推送样式 / 查看所属地图 / 新建切片 | ✓；`gsStyle` 后端裸返回 void，前端只能按 HTTP 200 判成功（已标注） |
| 元数据 | 保存 / 重新加载 / 删除 | ✓ `metaInsert` 路径无前导斜杠（已标注） |
| 活动 | 全部日志 `logList` | ✓ |

**评价**：抽屉页签的划分与端点群一一对应，无一个按钮落到不存在的端点；栅格「读取极值/唯一值」为分级设色提供参数来源，链路设计合理。

## 2. 数据接入（`#/ingest`）

**设计意图**：后端有两个互不相关的上传 Controller（`UploadController` 通用分片 + `KneeCoordinatesController` SHP 系列，后者**无类级前缀**、路径全大写开头），原型设独立页把两条通道并列呈现，而不是把上传藏进资源页弹窗——因为 SHP 通道是「整包上传后解析 WKT」，交互模型与分片上传不同。

| 按钮 | 端点 | 评价 |
|:---|:---|:---|
| 分片上传 | `AddFiles` → `FileMerge` → `Insert` → `UpdateStatus` 四步链路 | ✓ 弹窗内演示完整链路 |
| SHP 系列上传 | `POST /Kneecoordinates/UploadShpFiles`（multipart 多文件） | ✓ |
| 接入记录「查看」 | 行内 `api:'uploadMerge'` / `api:'shpWkt'` | ✓ 合并动作由前端分片完成后自动触发，不需要独立按钮，合理 |

## 3. 三维资源（`#/model3d`）

**设计意图**：三维有独立表 `sdms_model3d`、独立状态机（0 上传中→4 已发布/5 失败）、独立 MQ 转换、独立上传协议（init→part→complete→convert→publish-url），与 `layer_content` 完全不同构，所以独立成域，不从数据目录下挂。

| 按钮 | 端点 | 评价 |
|:---|:---|:---|
| 上传三维数据 | `POST /model3d/init` | ✓ 弹窗演示分片（5 MiB、`max-concurrent: 1`） |
| 下发转换 / 重试 | `POST /model3d/{id}/convert` | ✓ 仅对 st=1 可用（状态机约束） |
| 加载地址 | `GET /model3d/{id}/publish-url` | ✓ 预签 120 分钟，Cesium 直接加载；**没有下载按钮是有意的**——三维成果只经 URL 消费 |
| 详情 | `GET /model3d/page` | ✓ |
| 删除 | `m3dDelete` | ✓ |
| 转换任务 | 复用 `#/tasks` | ✓ |

`m3dComplete`（分片合并）无独立按钮——由上传器在最后一片后自动调用，合理省略。

## 4. 编目管理（`#/catalog/type|tag|tagrel`）

**设计意图**：接口模型里三个实体形态不同——分类是**树**、标签是**扁平表**、标签关系是**多对多中间表**（`sdms_tag_releation`），所以拆三页而不是塞进一个「设置」页；标签关系独立成页是 v3 相对 v2 的关键补全。

| 页面 | 按钮 | 评价 |
|:---|:---|:---|
| 数据分类 | CRUD + 排序 `updateList` + 详情 | ✓ |
| 数据标签 | CRUD + 批量打标 | ✓ |
| 标签关系 | 批量建立关联 / 按地图反查 / 编辑 / 解除 | ✓ `tagRelByMap` 在地图工作台也有入口（同一端点两个入口，合理） |
| 字典管理（系统域） | 分类新增 + 代码项 CRUD | ⚠️ P2：`dicTypeUpdate`/`dicTypeDelete` 后端有、UI 无入口 |

## 5. 样式与符号（`#/style`、`#/symbol`）

**设计意图**：样式分矢量（分级/唯一值/单一符号）与栅格（灰度拉伸/分级设色/三波段）两族，端点共享一套 `dataStyle`；色带与样式分离（`rampsByName` 可整体换色带）。

| 按钮 | 端点 | 评价 |
|:---|:---|:---|
| 新建样式 | `styleInsert` | ✓ |
| 重名校验 | `POST /dataStyle/IsExists` | ✓ **保存前自动调用**，好设计 |
| 解析 SLD / 反向解析 | `Parsethefile` / `ParsingSld` | ✓ 导入与逆向两条路 |
| 编辑 / 删除 | `styleUpdate` / `styleDelete` | ✓ 删除前先「校验引用」`GetMapReleationByStyle`，防悬挂引用，好设计 |
| 色带库 / 换色带 | `rampsLinear` / `rampsByName` | ✓ |
| 推送 GeoServer | `InsertGeoServerStyle` | ⚠️ P2：裸返回 void，建议后端补返回值 |
| 文件夹 | `styleFolders` | ⚠️ P2：`folderAdd/folderUpdate/folderDelete` 无按钮 |
| 符号库 | 新增 / 删除 / 刷新 | ⚠️ P2：缺 `symbolUpdate`/`symbolDetail` 编辑入口 |

## 6. 地图与发布（`#/map`、`#/publish`）

**设计意图**：地图 = 图层组合（`MapRelation` 中间表）+ 比例尺区间 + 图例；发布是 `mapreleation/PublicMap` 一次性产出三维。TOC 的增删改全部走 `MultiInsert/MultiUpdate/Delete` 三个端点，勾选态与顺序即所见即所得。

### 地图工作台

| 按钮 | 端点 | 评价 |
|:---|:---|:---|
| 新建地图 | `POST /map/Insert` | ✓ |
| 发布地图 | `POST /mapreleation/PublicMap` | ✓ |
| 刷新 | `POST /mapreleation/RefreshMap` | ✓ 刷新地图缓存 |
| 重算四至 | `POST /map/UpdateMapBBox` | ✓ 按图层 bbox 回写，加图层后应提示调用 |
| TOC ＋ / 保存 / 移除 | `MultiInsert` / `MultiUpdate` / `marDelete` | ✓ |
| 保存比例尺 | `POST /mapreleation/MultiUpdateScale` | ✓ 同步上传 GeoServer（已标注） |
| 点选取值 / 点选查询 | `getLayerValue` / `pageAttrInfoByPoint` | ✓ 分工明确：前者取值（画布悬浮/拾取），后者弹属性面板 |
| 更新图例 / 设置分类 / 标签 | `UpdateMapLegend` / `UpdateDataType` / `tagRelByMap` | ✓ |
| TOC ✕ | `marDelete` 删除**关联** | ⚠️ 与 §8-2 相关：只能删图层关联，删不掉地图本体 |

### 服务与缓存

| 按钮 | 评价 |
|:---|:---|
| 服务地址 / 能力文档 / 复制 | ✓ `serverInterface` |
| 新建切片任务 / Seed | ✓ `IsExistTilesTask` + 任务模型复用 |
| 清理 | ✓ `toolDelete` 删任务记录 |
| 停止 | ⚠️ P2：绑的是 `toolList`（查询），后端**没有取消任务的端点**，只有删记录；按钮应改「查看」或后端补 cancel |

**❌ P1（§8-2）**：`mapDetail`/`mapUpdate`/`mapDelete` 三个端点在注册表里存在，但**整个 UI 没有任何入口**——地图列表卡片上既不能改名改描述，也不能删除地图。地图工作台目前「只能动 TOC、动不了地图」。

## 7. 处理与分析（`#/tools`、`#/tasks`、拓扑）

**设计意图**：10 类工具共用 `sdms_tool_his` + `origin` 1~10 + taskId 轮询 + `storageLayer` 入库，因此收敛为一个工具箱（页内三类切换）+ 一个任务中心；「运行」按钮动态绑定当前工具自己的提交端点（`data-api="${cur.api}"`）。

| 按钮 | 端点 | 评价 |
|:---|:---|:---|
| 运行 | 按工具动态（`cutLayer`/`reclass`/`interUnion`…） | ✓ 一套弹窗承载四段式：提交 → taskId → 轮询 → 成果入库 |
| 表单辅助：读取极值 / 自然断点 / 唯一值 / 选色带 | `tifMaxMin` / `tifJenks` / `tifValues` / `rampsByName` | ✓ **好设计**：分级参数由后端算好填入，用户不手填 |
| 成果入库 | `GET /layerTool/storageLayer?id&targetId` | ✓ **好设计**：任务完成 ≠ 入库，用户显式选目标目录后才置 `storage=1` 并上图 |
| 删除任务 | `toolDelete` | ✓ |
| 拓扑状态 / 检查 / 创建 / 挂列 / 同步 / 删除 | `topology/*` 六端点 | ✓；`topoImport`/`topoAddColumn` 无入口（P2） |
| 任务「日志」 | `toolList` | ⚠️ P2：后端无任务级日志端点，`sdms_tool_his` 只有任务记录；按钮实为「查看历史」，措辞需改 |

## 8. 问题清单（按优先级）

### P1（进开发前必须定案）

| # | 问题 | 证据 | 建议 |
|:---|:---|:---|:---|
| 1 | **删除语义不一致**：列表「批量删除」绑 `POST /layerContent/Delete`（不连带清理发布），详情抽屉「删除」绑 `POST /layerContent/DeleteLayer`（连带）。批量删除已发布图层会留下孤儿发布信息 | `pageCatalog` vs `drawer` | 统一改用 `DeleteLayer`（批量场景前端循环），或后端补批量删除端点 |
| 2 | **地图本体无管理入口**：`mapDetail` / `mapUpdate` / `mapDelete` 端点存在但 UI 零引用，地图不能改名、改描述、删除 | `pageMap` 只有 TOC 级操作 | 地图列表卡片加「编辑 / 删除」；删除前校验 `GetAllListByMapId` 是否有关联图层 |
| 3 | **日志「导出」无端点支撑**：按钮标 `logList`，但那是分页查询；后端无日志导出端点 | `pageLog` | 短期：前端分页拉全量后本地生成 CSV；长期：后端补 `/layerLog/export` |

### P2（CRUD 补全，不阻塞）

| # | 问题 | 涉及端点 |
|:---|:---|:---|
| 1 | 批量导出 / 批量发布复用单图层端点 | `attrDownload` / `publishService` 循环调用 |
| 2 | 字段行内缺编辑/删除按钮 | `fieldUpdate` / `fieldDelete` |
| 3 | 属性表缺新增/删除记录按钮 | `attrInsert` / `attrDelete` / `attrUpdateList` |
| 4 | 字典分类缺编辑/删除 | `dicTypeUpdate` / `dicTypeDelete` |
| 5 | 符号库缺编辑/详情 | `symbolUpdate` / `symbolDetail` |
| 6 | 样式文件夹缺增删改；`gsStyle` 裸 void | `folderAdd/folderUpdate/folderDelete` |
| 7 | 切片「停止」无取消端点；任务「日志」措辞 | 后端补 cancel 或改按钮措辞 |
| 8 | 拓扑规则导入/加列无入口 | `topoImport` / `topoAddColumn` |
