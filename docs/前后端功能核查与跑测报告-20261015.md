## 三、本轮发现并修复的缺陷

### 3.1 manage 目录树 dictType 取值错误（P0，已修）
- 现象：主通道 `getLayerTree` 从未被请求，页面落兜底 category 模式。
- 根因：`loadDictOptions` 取 `first.code/first.dictCode`——字典项实体无此字段 → `dictType=''` → 跳过主通道。
- 修复：改取 `typeCode`，**优先「数据分类」(data_type)**；下拉数据源改字典分类列表（`dicDataType/GetAllList`），value=typeCode。
- 验证：`getLayerTree?dictType=data_type → 200`，树渲染 2 根目录。

### 3.2 manage 兜底树「无限请求循环」（P0，已修）
- 现象：进入 manage 页后 `getLayerTreeByType` 请求不断（dataTypeId=94,96,98… 无限递增），3 秒 50+ 请求。
- 根因：三处叠加——① 懒加载回调用 `node.id`（el-tree **内部数字 id**，非业务 id）；② `:default-expand-all` 与 `:lazy` 组合导致全量节点展开触发 load；③ 回调内 `node.totalLayerCount=…` 回写响应式数据 → 树重绘 → 新一轮 load。
- 修复：`node.data.id` 取业务 id；去掉 default-expand-all；去掉响应式回写；加子树缓存防重。
- 验证：循环消失，仅 1 次主通道请求。

### 3.3 style 页查询参数导致后端 500（P1，已修）
- 现象：样式列表恒空（「暂无样式数据」）。
- 根因：前端传 `{name: …}`，后端 `DataStyleInputDto` 无 `name` 字段且未忽略未知字段 → `HttpMessageNotReadableException` → 500。
- 修复：前端改传 `styleName`；后端 DTO 加 `@JsonIgnoreProperties(ignoreUnknown = true)` 兜底（防同类字段差异再炸）。
- 验证：样式列表返回 2 条；`{name:""}` 兼容不再 500。

### 3.4 ColorBrewer.xls 缺失 → 色带库不可用（P1，已修）
- 现象：`/dataStyle/GetLinearColorRamps` 抛「颜色配置文件加载失败: Data\ColorBrewer.xls」→ 500。
- 根因：迁移时该数据文件缺失（代码从 `工作目录/Data/ColorBrewer.xls` 读取）。
- 修复：① 生成标准 ColorBrewer 色板 xls（14 组：seq 6 / div 4 / qual 4，`Data/ColorBrewer.xls` + `geodata-web/src/main/resources/Data/` 双份）；② `ColorRampPlus` 增加 `classpath:` 回退（jar 自带资源，部署免手工放置）。
- 验证：接口 200 返回 Blues 等色板。

### 3.5 数据对齐：目录 dictCodeID（已修）
- demo 目录 dictCodeID 统一为字典分类「数据分类」的 typecode `data_type`（新增该字典分类行）；与前端 dictType 下拉、`getLayerTree` 过滤一致。**原系统实际取值需确认（见待确认项）。**
