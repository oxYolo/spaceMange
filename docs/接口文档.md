## 0. 通用约定

### 0.1 统一返回体 `Result<T>`

```json
{
  "code": 200,
  "success": true,
  "result": {},
  "msg": "操作成功"
}
```

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| code | int | 业务状态码 |
| success | boolean | `code == 200` 时为 `true` |
| result | T | 业务数据载荷 |
| msg | string | 提示信息 |

`ResultCode` 状态码取值：

| 码值 | 常量 | 含义 |
|:---:|:---|:---|
| 200 | SUCCESS | 成功 |
| 400 | FAILURE | 业务失败（默认失败码） |
| 401 | UNAUTHORIZED | 未认证 |
| 403 | FORBIDDEN | 无权限 |
| 404 | NOT_FOUND | 资源不存在 |
| 405 | METHOD_NOT_ALLOWED | 方法不允许 |
| 500 | INTERNAL_SERVER_ERROR | 服务内部错误 |

工厂方法：`Result.data(T)`（msg 默认「操作成功」）、`Result.data(T,msg)`、`Result.data(code,data,msg)`、`Result.status(boolean)`、`Result.success(String)`、`Result.fail(int,String)`、`Result.fail(String)`（默认 400）。

> ⚠️ **注意**：源工程中有若干端点**未包裹 Result**，直接返回裸类型（`boolean` / `String` / `ListResultOutput` / `PagedResultOutput` / `MapEntity` / `Integer`）。迁移保持 1:1 契约，此类端点已在下文逐个标注 **「裸返回」**。前端对接时需注意。

### 0.2 分页与列表结构

**`PagedResultOutput<T>`**

```json
{ "totalCount": 100, "items": [] }
```

**`ListResultOutput<T>`**（注意字段名为单数 `item`）

```json
{ "item": [] }
```

**`PageResultDTO<T>`**（空间查询专用）

```json
{ "records": [], "layerName": "", "layerId": "", "total": 0 }
```

**分页参数命名不统一**（源工程历史遗留，迁移保持）：`pageSize` / `pageIndex`（小驼峰）、`PageSize` / `PageIndex`（大驼峰）。下文每个端点按源码实际书写标注。

### 0.3 认证与用户信息

- 用户身份通过 `AuthUtil.getNickName()` 从当前请求上下文获取（whulri 基座集成）。
- 部分端点仍保留显式 `user` / `userAccount` 参数（源工程遗留），如 `MapController.Delete(id, user)`。

### 0.4 异步任务通用模型

**图层工具（裁剪/重采样/重分类/擦除/缓冲区/交并补/叠加计算/栅格矢量化/矢量栅格化）** 统一为异步模式：

```
POST 工具端点 → 建 sdms_tool_his 任务记录(status=0) → 投递 LayerToolExchange/LayerToolRouting → 返回 taskId
GET  /layerTool/getList?origin=N → 轮询任务状态
POST /layerTool/storageLayer?id&targetId → 任务成功后将成果图层入库显示
```

`sdms_tool_his` 关键字段：`Id`、`layerId`、`layername`、`layerattrttable`、`createdt`、`createby`、`status`(0 计算中 / 1 成功 / 2 失败)、`origin`(工具类型 1~10)、`storage`(0 未存储 / 1 已存储)、`uploadfiletype`、`detailjson`。

**`origin` 取值对照表**

| origin | 工具 | 对应端点 | taskType |
|:---:|:---|:---|:---:|
| 1 | 图层裁剪 | `/layerTool/cutLayer` | 1 |
| 2 | 重采样 | `/layerTool/resample` | 2 |
| 3 | 栅格矢量化 | `/layerTool/tifToShp` | 3 |
| 4 | 矢量栅格化 | `/layerTool/shpToTif` | 4 |
| 5 | 重分类 | `/layerTool/reclassification` | 5 |
| 6 | 擦除 | `/layerTool/eraseVectorLayer` | 6 |
| 7 | 缓冲区 | `/layerTool/bufferZone` | 7 |
| 8 | 矢量交并补 | `/layerTool/intersectionAndUnion` | 8 |
| 9 | 栅格叠加计算 | `/layerTool/overlayCalculation` | 9 |
| 10 | 拓扑检查 | `/topology/check` | — |
| 10 | 三维数据转换 | Model3d 模块 | — |

**MQ 拓扑**

| 交换机 | 路由键 | 队列 | 消费者 |
|:---|:---|:---|:---|
| `LayerToolExchange` | `LayerToolRouting` | — | 图层工具后台服务 |
| `TopologyExchange` | `TopologyRouting` | `TopologyQueue` | `TopologyQueueHandler`（MSG_TYPE=`TopologyCheck`） |
| `Model3dConvertExchange` | `model3d.convert` | `Model3dConvertQueue` | `Model3dConvertQueueHandler` |

**实时进度推送**：通过 Microsoft SignalR 客户端推送至 .NET IM 服务（`imservice.imIP:imPort`，默认 `127.0.0.1:5000`，`isEnableSSL=false`）。

## 18. 三维数据管理 `Model3dController`（`/model3d`，9 个端点）**（迁移工程新增）**

> 统一成果格式 **3D Tiles**，对象托管 MinIO，转换链路通过 `ConvertCommandBuilder` SPI 路由多工具链。

### 18.1 三维数据状态机

| 值 | 枚举 | 含义 |
|:---:|:---|:---|
| 0 | `UPLOADING` | 上传中 |
| 1 | `UPLOADED` | 上传完成，待下发转换 |
| 2 | `QUEUED` | 转换任务已入队 |
| 3 | `CONVERTING` | 转换中 |
| 4 | `PUBLISHED` | 已发布（可签发加载地址） |
| 5 | `FAILED` | 失败（`failReason` 记录原因） |

**状态流转**

```
init ──> UPLOADING ──(complete)──> UPLOADED ──(convert)──> QUEUED ──> CONVERTING ──> PUBLISHED
                            │                                                  │
                            └── TILESET 类型：直接 PUBLISHED ──────────────────┘
                                                                               └──> FAILED
```

### 18.5 稳定性加固说明（2026-10-10）

| 项 | 做法 |
|:---|:---|
| **加载链路** | 3D Tiles 子瓦片走相对路径，预签名 URL 无法覆盖 → 发布前缀（`public-read-prefix`，默认 `model3d/`）设匿名只读策略，`publish-url` 返回 `{public-base-url}/{bucket}/{key}`；单体 glb 一并走公开地址。`public-read=false` 时退回预签名（仅单文件有效） |
| **僵尸任务回收** | 转换期间每 `heartbeat-interval-ms`（30s）刷新 `heartbeat_time`；看门狗每 `watchdog-interval-ms`（60s）把心跳超 `stale-minutes`（15min）的「转换中」记录回收为失败；服务启动按 `convert_owner` 立即回收**本实例**残留任务（多副本安全） |
| **死信队列** | 主队列声明 DLX（`Model3dConvertDlxExchange` → `Model3dConvertDeadQueue`）兜底；转换失败消息由处理器手动转投该队列（带 `x-failure-reason`/`x-failed-at` 头）后再 ack |
| **断点续传** | 新增 `GET /model3d/{id}/parts` 返回已传分片号 |
| **磁盘预检** | 转换前按源体积 3 倍预检工作区可用空间，不足快速失败 |
| **产物校验** | 进程退出码 0 后校验产物：`tileset.json` 非空；单体 glb 校验魔数 `glTF`、体积下限 |

> 数据库：`sql/model3d_schema.sql` 已含 `convert_owner` / `heartbeat_time` 两列（前期阶段直接建表即可）。
> 部署：加载链路与队列注意事项见 `deploy/model3d/TOOLS-DEPLOY.md` 第 6、7 节，nginx 反代参考 `deploy/model3d/nginx-minio-proxy.conf`。
