# 前端架构与产品状态流

## 模块职责

```text
src/
  auth/                   登录页、认证接口、用户状态、会话和登录路由
  business/routes.ts      数据管理等业务页面的路由声明
  api/                    业务 HTTP 合约适配、错误归一、请求取消
  features/
    datasets/
      model.ts            数据模型、类型、操作能力
      query.ts            两类数据源的分页、排序与筛选
      services.ts         服务协议地址和切片进度读取
      repository.ts       将现有后端 API 接入领域服务
      cache.ts            短缓存、请求去重与失效规则
      ingestion.ts        详情校验矢量异步入库结果
      listState.ts        URL 查询条件的解析与恢复
      uploadValidation.ts 上传前的完整文件组校验
      composables/        上传表单和上传流程编排
      components/         上传抽屉、数据类型标记、空态与行操作
    tasks/
      model.ts            任务状态、成果入库准入
      useTaskCenter.ts    任务中心的查询与操作
  composables/usePolling.ts 串行轮询、可见性与卸载清理
  views/                  页面布局、筛选、对话框与交互
  utils/feedback.ts       用户可理解的统一错误提示
```

`App.vue` 在登录路径仅渲染独立登录页，访问业务路由时异步加载业务布局。登录页、认证 API、用户资料与会话状态集中在 `auth/`；业务页通过 `auth/store.ts` 读取当前用户。`auth/routes.ts` 与 `business/routes.ts` 分开声明，在路由入口合并；两侧共用 HTTP 请求与错误处理，不复制认证逻辑。业务页面仍使用动态导入，登录页不需要加载数据管理、地图等页面代码。

业务依赖方向为页面到领域服务，再由仓库适配现有 API。领域的查询、缓存与任务状态可独立测试。`utils/datasets.ts` 是旧页面的兼容导出入口。

## 数据与任务的使用流程

二维数据：选择类型与完整文件组 → 上传并入库 → 属性或影像检查 → 发布服务 → 复制地址 / 地图预览。栅格可进一步提交 WMTS 切片；切片期间已发布 WMS 仍可使用。

三维数据：上传 → 待转换 → 排队 / 转换 → 发布为 3DTiles；失败后可重试转换。现成 3DTiles 沿后端直传发布流程处理。

处理工具：提交任务 → 查看进度 → 成功且尚未入库时选择目录入库。任务数字状态以后端为准：`0` 处理中，`1` 成功，`2` 失败。未知值单独显示；origin 10 的报告/三维成果使用对应入口。删除任务记录不会取消后台计算。

处理中数据禁止提前发布或删除，确认框与请求过程共享防重入锁。上传期间不能关闭抽屉或离开页面，避免任务仍在执行但用户无法跟踪。切换上传类型会清空旧文件和续传状态。

## 上传编排与入库确认

`DatasetUploadDrawer.vue` 负责必填与选填字段、文件清单和可访问交互；`useDatasetUpload.ts` 编排请求；`uploadValidation.ts` 在创建服务器状态前校验文件组。SHP 必须选择同名 `.shp/.shx/.dbf`，可补充 `.prj/.cpg`；其他类型每次一个文件。多文件选择会完整保留并明确报错，不会静默取第一项。字段错误在修正后重新校验，请求失败保留表单与文件，支持重试。

二维请求沿用现有 `AddFiles → FileMerge → Insert → UpdateStatus`。文件大小记录完整文件组的 KB，入库请求携带主文件名；前端为图层预分配 GUID。`LayerContentInputDto.id` 接受该值，`insertLayerData` 仅在 ID 为空时生成新值，因此同一个 ID 可用于图层和先创建的 `LayerLog.layerId`。

真实矢量 Insert 只表示已提交导入，`ExcuteShpJob` 在后台完成属性和空间要素写入；`UpdateStatus` 只更新上传标记。`layerSpatialTable` 在导入前已分配，非空不能证明入库成功。上传完成提示为“文件已上传，正在入库”，列表中 `uploadStatus: 1` 默认显示“已上传”。`ingestion.ts` 对尚未发布的矢量补查详情：`isShow: 1` 或已发布是完成证据；详情缺失、`null/0` 均显示“入库待确认”，限制发布、属性和删除。工具成果也可能因待存储而保持 `isShow: 0`，不得据此判定失败。待确认状态可以在后续读取中恢复为已入库；不通过前端计时推断成功。

三维沿用 `init → part → complete`。OSGB、点云、单体和 BIM 上传完成后为“待转换”；现成 3DTiles 在 complete 中直接发布。续传先读取原任务，核对上传中状态、模型类型、文件名和大小，再调用分片续传。界面将文件传输、完成上传、入库和发布分别提示，文件传到 100% 时不声称后台处理已完成。

## 性能和一致性

- 单一数据源默认按后端上传时间倒序直接分页；混合源读取当前页所需前缀，再统一排序。
- 状态过滤、未发布筛选及全局升序需要后端尚未提供的筛选/排序能力，目前按最多 200 条分批读取候选数据，每源至多 4 个并发。大量数据时，后续应由后端补统一分页筛选端点；不能把当前页局部排序当全局排序。
- 查询缓存 5 秒，稳定地址缓存 30 秒，切片进度缓存 2 秒；相同在途请求复用。写操作使相关缓存失效，失效前的旧请求不能覆盖新数据。
- 缓存和异步结果按会话隔离；旧登录的 401、用户资料、退出和慢响应不能影响新登录。
- 栅格列表先展示摘要，再补充详情。打开详情或预览时才加载相关组件。
- 轮询串行调度；页面隐藏暂停，恢复可见后刷新，卸载时取消。暂时进度故障保留正在执行的任务状态并继续重试。

## 工作台交互

主管理页与栅格页使用 URL 保存已提交筛选、排序和分页，刷新、返回时恢复；草稿搜索输入不会触发查询。表格与卡片共享数据和操作组件，视图偏好保存在本地。加载失败会明确标注保留的上次结果；空数据与筛选无结果分别提供上传或清除筛选入口。

壳层页面入口使用语义链接，支持当前路由和分组展开状态；`/` 聚焦全局搜索，编辑内容和输入法期间不拦截。移动导航支持 Escape 关闭、焦点约束和关闭后回焦。高级入口按当前页面展开。

地图预览与详情按资源和请求代次隔离异步响应；切换协议、切换数据或关闭后，旧请求不能回填。预览错误提供重试；服务地址从真实后端返回，地图是否可加载以实际请求结果为准。

## 导出与快捷导航

快捷筛选只更新列表查询条件；URL 记录已提交的筛选与排序，刷新后可以恢复。批量复制在开始时冻结资源范围、限制并发，并在会话变化后放弃输出。清单 CSV 使用 UTF-8 BOM、完整引号转义及公式单元格防护，导出范围明确为当前页或已选资源。

快捷命令复用导航配置，仅支持页面和上传入口；搜索与按键逻辑单独测试，弹层处理输入法、焦点约束与恢复。服务接入只根据已返回的 URL 生成文本，保留额外参数；WMTS/MVT 网格来自能力文档，未确认的图层、版本与坐标不能猜测。

## 登录与业务路由

`#/login` 独立展示登录页面；业务路由没有登录守卫，可直接打开。登录接口和用户会话代码保留在 `auth/`，供后续正式接入认证服务。业务接口通过运行时地址配置和开发代理请求真实后端。

## 界面动效

`assets/styles/motion.css` 统一维护 160 / 240 / 360ms 时长、缓动、控件反馈和减少动态效果规则。页面切换只以路由 path 标识，筛选参数变化不重建页面；离场页面立即禁止交互。列表按稳定资源 key 错峰入场，上传文件用稳定 File key 保持移除与重排过程中的身份。地图画布不做缩放或持续动画；持续效果只用于实际处理中状态和进度。`prefers-reduced-motion` 开启时取消位移过渡与循环效果。

## 开发验证

```sh
npm ci
npm run check
npm run dev
```

`type-check` 明确检查 `tsconfig.app.json` 和 `tsconfig.node.json`；根 tsconfig 仅有 references，不能使用原来的空检查命令作为验收证据。

开发与生产构建均不包含本地 Mock 路由。后端业务代码与接口保持现状；真实认证、GIS 处理和 Docker 启动仍依赖对应后端及私有依赖。
